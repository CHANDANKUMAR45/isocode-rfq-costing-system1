# Isocode RFQ-to-Quote Costing Web Application

A full-stack manufacturing quotation management application designed to simplify the Request for Quotation (RFQ) to Quote process for machined and forged components.

The system helps manufacturing teams register customer RFQs, calculate part costs across multiple production volumes, manage effective-dated rates, and control quotation approvals through role-based access.


---

## 1. Project Overview

Manufacturing companies need to consider several factors when preparing quotations, including raw material prices, scrap recovery, machining operations, labour, overheads, packaging, freight, and GST.

Managing these calculations manually can make quotation preparation difficult and can make historical rate comparisons challenging.

The Isocode RFQ-to-Quote Costing Application brings these activities into one system.

It provides a structured workflow for:

- Registering and managing customer RFQs.
- Entering part and manufacturing operation details.
- Calculating costs across multiple production volumes.
- Maintaining effective-dated rate masters.
- Saving quotation rate snapshots.
- Managing high-value quotation approvals.
- Generating quotation PDFs.
- Searching historical quotation records.

## 2. Key Features

### Deterministic Part Costing Engine

The application uses server-side mathematical calculations to determine quotation prices.

Cost components include:

- Gross raw material cost.
- Scrap recovery credit.
- Net material cost.
- Machining and operation costs.
- Setup time and cycle time.
- Machine and labour costs.
- Factory overhead.
- Packaging and freight.
- Contribution margin.
- GST calculation.

AI is not used for costing arithmetic or quotation approval.

### Multi-Volume Costing

Calculate and compare costs across different production batch volumes.

The costing engine considers setup time amortization across the selected batch quantity, helping estimators compare production economics at different volumes.

### Effective-Dated Rate Masters

Maintain material and machine rates with effective start and optional end dates.

The application includes rate categories such as:

- Raw materials: EN8, 40Cr4, 20MnCr5, SS304.
- Machines: CNC Turning, 4-Axis VMC, Forging Press, Cylindrical Grinder.
- Labour rates.

### Immutable Quotation Rate Snapshots

Each saved quotation retains a snapshot of the rates used during its calculation.

Later rate changes do not rewrite the previously saved quotation snapshot.

### Commercial Approval Workflow

Quotations with annual pre-GST value greater than ₹25,00,000 require Sales Head approval.

- Quotations at or below ₹25 lakh can proceed without Sales Head approval.
- Quotations above ₹25 lakh enter the pending approval workflow.
- Only Sales Heads can approve or reject eligible quotations.
- Rejection requires a reason.
- Approval and rejection activities are recorded.

### AI-Assisted RFQ Intake

The application supports extraction of suggested fields from pasted RFQ text using Google Gemini when configured.

Features include:

- Field extraction suggestions.
- Source text snippets.
- Confidence information.
- Suggested manufacturing operations.
- Estimator review and manual correction.
- Local heuristic parser as a fallback.

**Important:** AI is optional and does not determine quotation prices. The text scrubber removes selected email addresses, phone numbers, and confidentiality phrases, but it cannot guarantee removal of all customer or drawing identifiers. Only submit information authorized for external processing. Use the local parser for restricted information.

### PDF Quotation Generation

Generate quotation PDFs containing relevant customer, RFQ, part, costing, and commercial information.

PDFs are generated by the backend when requested.

### Historical Quotation Search

Search historical quotation records already stored in the database.

The application includes illustrative historical sample records for local development.

### Role-Based Access Control

The application supports three user roles:

| Role | Main Responsibilities |
|---|---|
| Estimator | Create eligible RFQs, prepare costings, submit quotations, and use RFQ intake |
| Sales Head | Review eligible quotations, approve or reject them, and manage material and machine rate versions |
| Admin | Manage users and roles, and view audit records |

The backend enforces role permissions. Frontend visibility controls are not treated as a replacement for server-side authorization.

### Audit Logging

Important operations, including quotation and approval activities, are recorded for review.

## 4. Application Architecture

The application follows a client-server architecture.

```text
              User / Browser
                    |
                    v
          React + TypeScript + Vite
                    |
               REST API
                    |
                    v
             Express Backend
                    |
       +------------+-------------+
       |            |             |
       v            v             v
 Authentication  Costing       Workflow
   and RBAC       Engine        Services
       |            |             |
       +------------+-------------+
                    |
                  Prisma
                    |
             +------+------+
             |             |
             v             v
           SQLite      PostgreSQL
```

### Architecture Highlights

- Frontend and backend are maintained separately.
- Business logic and costing calculations run on the server.
- Prisma handles database operations.
- Database selection is controlled through `DATABASE_URL`.
- Role permissions are checked by the backend.
- Quotation snapshots preserve the rates used for saved quotes.

## 5. Main RFQ-to-Quote Workflow

1. An Estimator logs in and creates a customer RFQ.
2. The Estimator enters part, material, quantity, and operation details.
3. The Estimator can use manual entry or review AI-assisted extraction suggestions.
4. The server calculates quotation values for the configured volume tiers.
5. The application saves quotation details and the rate snapshot.
6. The annual pre-GST quotation value determines whether approval is required.
7. A Sales Head reviews eligible pending quotations.
8. Approved quotations proceed to the `SENT` RFQ workflow state.
9. Authorized users can generate and preview quotation PDFs.

### Approval Rules

| Annual pre-GST quotation value | Workflow |
|---|---|
| ₹25,00,000 or below | No Sales Head approval required |
| Greater than ₹25,00,000 | Sales Head approval required |

The comparison uses a strict greater-than condition.

The application records quotation release as a workflow state. It does not currently send quotation emails or otherwise dispatch documents to customers.

## 7. Local Setup Guide

### Prerequisites

- Node.js 18 or later.
- npm.
- Git.

### Step 1: Clone the repository

```bash
git clone https://github.com/CHANDANKUMAR45/isocode-rfq-costing-system1.git
cd isocode-rfq-costing-system
```

### Step 2: Install dependencies

```powershell
npm --prefix server ci
npm --prefix client ci
```

### Step 3: Configure environment variables

```powershell
Copy-Item .env.example server\.env
```

Configure the following variables in `server/.env`:

| Variable | Purpose |
|---|---|
| `DATABASE_URL` | Database connection |
| `JWT_SECRET` | Private JWT signing secret |
| `DEMO_USER_PASSWORD` | Local demo account password |
| `PORT` | Backend API port |
| `GEMINI_API_KEY` | Optional Gemini API key |
| `GEMINI_MODEL` | Optional Gemini model |

Use a unique JWT secret of at least 32 bytes and a demo password of at least 12 characters.

Never commit real secrets or API keys.

### Step 4: Initialize a new SQLite database

For a new local database only:

```powershell
npm --prefix server run prisma:generate
npm --prefix server run prisma:push
npm --prefix server run seed
```

These commands initialize the database and create sample records.

Do not run schema or seed commands against a database containing important data without first making a backup.

### Step 5: Start the backend

Open the first terminal:

```powershell
npm --prefix server run dev
```

Backend API:

`http://localhost:5000`

### Step 6: Start the frontend

Open a second terminal:

```powershell
npm --prefix client run dev
```

Frontend:

`http://localhost:5173`

### Step 7: Open the application

Visit:

http://localhost:5173

For PostgreSQL setup, existing database migrations, and additional environment details, see [deployment.md](./deployment.md).

## 10. Security Considerations

- Passwords are stored as password hashes.
- Protected API routes use JWT authentication.
- Backend authorization checks the current database role.
- Environment variables are used for private configuration.
- Quotation calculations are performed on the server.
- Important operations are recorded in audit logs.
- The optional AI text scrubber has limited coverage and is not a guarantee of confidentiality.
- Demo accounts and sample data are not suitable for production.

Before production deployment, additional configuration is required, including HTTPS, restricted CORS origins, secure secret storage, rate limiting, database backups, and operational monitoring.

---

## 11. Current Limitations

- The application is not deployed to a live hosting service.
- JWT bearer tokens are stored in browser `localStorage`.
- Spreadsheet import is not available in the user interface.
- The API has a restricted bulk-import endpoint, but no spreadsheet parser.
- Labour rates can be read, but there is no labour-rate write screen.
- Admin functionality does not include account deactivation or password reset.
- RFQ editing currently supports the primary part only.
- Email delivery and automatic customer dispatch are not implemented.
- No dedicated frontend automated test suite is configured.
